02 The one graph, solved five ways

Learn the five search algorithms on a single graph so you see exactly how they differ. Same start S, same goal G, same edge costs. Only the rule for which node to expand next changes.

Edges (directed): S→A=1, S→B=4, A→B=2, A→C=5, B→C=1, B→D=5, C→D=3, C→G=7, D→G=2. Heuristics (straight-line guess to G): h(S)=7, h(A)=6, h(B)=4, h(C)=4, h(D)=2, h(G)=0.

03 Uniform Cost Search (UCS)

Expand the frontier node with the smallest cumulative cost g(n). It is Dijkstra's algorithm. This is the single most-asked question in the course.

Method — write it exactly like this

  1. Keep a frontier as a priority queue of paths, ordered by total cost g. Start with S:0.
  2. Pop the cheapest path. If its last node is the goal → stop, report path + cost.
  3. Otherwise move that node to the explored set and add each neighbour with g = g(parent) + edge.
  4. If a node is already in the frontier with a higher cost, keep the cheaper one.
  5. Repeat. Show the frontier and explored set at every step — that's where the marks are.

Worked trace (the graph above)

Frontier {S:0} Explored { } pop S(0) → add A:1, B:4 Explored {S} Frontier {A:1, B:4} pop A(1) → B:1+2=3 (beats 4), C:1+5=6 Frontier {B:3, C:6} Explored {S,A} pop B(3) → C:3+1=4 (beats 6), D:3+5=8 Frontier {C:4, D:8} Explored {S,A,B} pop C(4) → D:4+3=7 (beats 8), G:4+7=11 Frontier {D:7, G:11} Explored {S,A,B,C} pop D(7) → G:7+2=9 (beats 11) Frontier {G:9} Explored {S,A,B,C,D} pop G(9) → GOAL Path: S → A → B → C → D → G Cost = 9
Trap: UCS is goal-tested when you pop it off the frontier, not when you first generate it. If you'd stopped when G was first added at cost 11, you'd get the wrong answer. Pop-then-test.
Vacuum-cleaner version (fully-text problem, no graph given). States = (robot room; dirt of L,R). Actions Left=5, Right=10, Clean=15. Start = robot Middle, L&R dirty. Cheapest plan: Right(10) → Clean(15) → Left(5) → Left(5) → Clean(15) = 50 — go right first, because the two return moves are cheap Lefts. The tempting left-first plan costs 55 (two expensive Rights back). Optimal cost is 50; full UCS trace is Drill 5 in the trainer.

04 BFS & DFS

Both ignore edge cost for choosing the next node — they differ only in order. Insert successors alphabetically (the papers always say so). Show frontier, explored set, tree, path, and path-cost.

BFS — breadth first (FIFO queue)

  1. Frontier is a queue (first-in-first-out).
  2. Expand the front node; add unseen neighbours (alphabetical) to the back.
  3. Explores level by level. First goal found = shallowest.

DFS — depth first (LIFO stack)

  1. Frontier is a stack (last-in-first-out).
  2. Always dive into the first (alphabetical) child before its siblings.
  3. Explores one branch all the way down, then backtracks.

Worked trace (same graph)

BFS

Frontier: S → S-A, S-B → S-B, S-A-C → S-A-C, S-B-D → S-B-D, S-A-C-G Explored: S, A, B, C Path: S-A-C-G Cost = 1+5+7 = 13

DFS

Frontier (stack): S → push A, B → pop B (last pushed) → push C, D → pop D → G generated Explored: S, B, D Path: S-B-D-G Cost = 4+5+2 = 11

Convention (official answer scripts): push children alphabetically — the alphabetically last child pops first. State your convention on the script.

BFS reaches G in 3 edges (S-A-C-G) but pays 13. DFS plunges to depth 5. Neither chose the cheap path — they don't look at cost.

Completeness & optimality — the memorized answer

BFS is complete and optimal*
Complete: it searches level by level, so even with an infinite tree it will always reach a goal if one exists.
Optimal: the first goal it finds is the shallowest — so it's optimal only when every step costs the same (unit cost). With varying costs, use UCS instead.
DFS is neither complete nor optimal
Not complete: on an infinite/deep branch it dives forever and may never reach the goal.
Not optimal: it returns the first path it stumbles into, which may be far more expensive than the best one.

*BFS space complexity O(bᵈ) is its real weakness — it stores the whole frontier. DFS wins on memory: O(bd).

05 A* Search

Expand the node with the smallest f(n) = g(n) + h(n) — cost so far plus heuristic guess to the goal. Best of UCS and Greedy combined.

Method

  1. For each frontier node compute f = g + h.
  2. Expand the smallest f. Break ties however the paper says (often alphabetical).
  3. Goal-test when popped. Keep the cheaper copy of repeated nodes.
  4. Write each node as g + h = f so the marker sees your working.

Worked trace (same graph)

S: 0+7=7 expand S → A:1+6=7 , B:4+4=8 expand A(7) → B:3+4=7 (beats 8) , C:6+4=10 expand B(7) → C:4+4=8 (beats 10) , D:8+2=10 expand C(8) → D:7+2=9 (beats 10) , G:11+0=11 expand D(9) → G:9+0=9 (beats 11) expand G(9) → GOAL Path: S → A → B → C → D → G Cost = 9 (optimal)
Why A* here is optimal: the heuristic never over-estimates the true remaining cost (it's admissible) — so A* is guaranteed to return the cheapest path. See §09.
Also seen: the GBFS-then-actual-cost combo (Fall 2024-25 Q5). With h(S)=22, h(A)=20, h(B)=8, h(C)=14, h(D)=11, h(G)=0: run A* on g+h, and separately run GBFS on h alone. They often reach the goal by different paths — that contrast is the point of the question.

06 Greedy Best-First Search (GBFS)

Expand the node with the smallest h(n) only — pure "how close does it look." Fast, but blind to how much you've already spent, so not optimal.

Worked trace (same graph)

expand S (h=7) → A:h6 , B:h4 pick B (lowest h) expand B (h=4) → C:h4 , D:h2 pick D expand D (h=2) → G:h0 pick G expand G → GOAL Path: S → B → D → G Cost = 4+5+2 = 11 (not optimal — A* found 9)

Present it as an open list / closed list if the paper asks (open = frontier, closed = explored). Same idea, different words.

Don't confuse GBFS with A*. GBFS ranks by h. A* ranks by g+h. One letter of difference, but GBFS drops optimality.

07 Depth-Limited (DLS) & Iterative Deepening (IDS)

DLS — Depth-Limited Search

DFS with a hard depth limit ℓ. Nodes deeper than ℓ are never expanded.

  • Q style: "list the order nodes are evaluated, depth limit = 3." Just do DFS but stop descending past level 3.
  • Incomplete if the goal is deeper than ℓ. Not optimal.

IDS — Iterative Deepening

Run DLS with limit 0, then 1, then 2, … until the goal is found.

  • Complete (finite b) and optimal for unit step costs — like BFS.
  • Uses DFS memory O(bd) — like DFS.
  • Re-expanding upper levels is cheap; it's the best uninformed search when you don't know the depth.

09 Admissible & consistent — "can we use A*? is it optimal?"

This is the "explain your answer" question that follows a graph. Learn the two definitions and the one-line test.

Admissible heuristic
h(n) ≤ h*(n) — the heuristic never over-estimates the true cheapest cost from n to the goal. Guarantees A* (tree search) is optimal.
Consistent (monotonic) heuristic
h(n) ≤ cost(n,n′) + h(n′) for every edge — the estimate never drops by more than the real step. Guarantees A* (graph search) is optimal. Consistent ⇒ admissible (not the reverse).
How to answer "Is it possible to solve this graph with A*?"
Yes — A* works on any graph with a defined heuristic. It is complete (finds a solution if one exists) and, provided the heuristic is admissible, it is optimal. Then check one or two nodes: e.g. at S, h(S)=7 ≤ true cost 9 ✓, so the heuristic doesn't over-estimate → optimal path guaranteed.
A* is always complete and optimal — memorize the caveat: "complete and optimal provided the heuristic is admissible (and consistent for graph search)." Examiners want that condition, not just "yes."

10 Alpha-Beta Pruning

Minimax that skips branches that can't change the result. α = best MAX has guaranteed so far; β = best MIN has guaranteed so far.

Rules

  1. Start every node with α = −∞, β = +∞; pass them down.
  2. At a MAX node, raise α to the best child value. At a MIN node, lower β.
  3. Prune the moment α ≥ β (equivalently β ≤ α): the remaining children of that node are cut — don't evaluate them.
  4. Evaluate left to right. Report which leaves were skipped.

Tiny worked example

MAX (root) / \ MIN B MIN C / \ / \ 3 5 2 (9) ← pruned B: sees 3 → β=3; sees 5 (5>3, MIN keeps 3) → B = 3 root MAX: α = 3 C: sees 2 → β=2. Now β(2) ≤ α(3) → PRUNE the 9. root = max(3, 2) = 3

On the big exam tree you do exactly this, left to right, writing each α/β update next to the node and crossing out every pruned branch. In the Fall 2024-25 tree, branches under F and P get pruned because α ≥ β there.

Most-lost marks: forgetting to carry α/β downward to children, and pruning on > only — the cut fires on α ≥ β (equal counts).

11 Formal problem definition + state space

"Describe this robot task as a search problem." Always the same five components, then two numbers. Template below — swap in whatever robot they give (garden 4×5, wall 12×12, maze 3×3).

The five components (garden-watering robot, 4×5 = 20 cells)

Initial state
Robot at its start cell; all 20 squares unwatered.
Actions
{ Up, Down, Left, Right, Water }.
Transition model
A move changes the robot's cell (if not off-grid); Water marks the current cell watered.
Goal test
All 20 squares are watered.
Path cost
1 per action (total number of actions).

State-space size

= (robot positions) × (watered/not for each cell)

= 20 × 2²⁰ = 20,971,520

Wall-painting 12×12 → 144 × 2¹⁴⁴. Maze n cells with no "paint" state → just n reachable cells.

Branching factor

Max number of actions from a state.

b = 5

(4 moves + Water). Fewer at edges/corners. Branching factor = actions per node; state space = total distinct states — don't mix them up, that's a common sub-question.

Well-defined problem (the 8-puzzle version)

Yes, the 8-puzzle is well-defined. A problem is well-defined when its initial state, actions, goal test, and path cost are all clearly specified (+ transition model). For the 8-puzzle: initial = the given board; actions = slide blank U/D/L/R; goal test = board equals goal arrangement; path cost = 1 per slide. All unambiguous → well-defined.

15 Agent types (draw the schematic)

A "draw the schematic and describe" question. All are the agent-program-in-environment box with sensors in, actuators out — they differ by what's inside.

┌──────────────── AGENT ────────────────┐ │ │ │ State ──▶ "What the world is │ │ ▲ like now" │ │ │ │ │ │ [Model: ▼ │ │ how world [Goals] / [Utility fn] │ │ evolves] │ │ │ │ ▼ │ │ └──── "What action is best" ───────┼──▶ Actuators │ ▲ │ └────────────────────┼───────────────────┘ Sensors ───────┘ (Environment)

Model-based reflex

Keeps internal state + a model of how the world evolves, to handle partial observability. Acts on condition-action rules.

Goal-based

Adds an explicit goal. Chooses actions that move toward the goal — uses search/planning. More flexible than reflex.

Utility-based

Adds a utility function that scores how good each state is, not just goal/not-goal. Picks the action maximizing expected utility — best when goals conflict or are uncertain.

16 Turing Test & the four approaches to AI

Turing Test (Acting Humanly)

A machine is "intelligent" if a human interrogator, chatting via text with a hidden human and the machine, cannot reliably tell which is which. To pass it a machine needs: natural-language processing, knowledge representation, automated reasoning, machine learning. The Total Turing Test adds computer vision + robotics (physical interaction).

The four approaches (a 2×2)

Acting humanly
Turing-test approach — behave like a person.
Thinking humanly
Cognitive modeling — mimic human thought.
Thinking rationally
"Laws of thought" — formal logic.
Acting rationally
Rational-agent — do the thing that maximizes expected performance. (Modern AI's stance.)

17 Quick short-answers

Tree search vs Graph search

Tree search keeps no record of visited states — it can revisit the same state and loop forever on cycles. Graph search keeps an explored/closed set and never expands the same state twice — avoids cycles and redundant work (costs memory).

The f(n) = (2−w)·g(n) + w·h(n) trick

wf becomes= which strategy
02·g(n)ranks by g only → Uniform Cost Search
1g(n)+h(n)→ A* search
22·h(n)ranks by h only → Greedy Best-First

More weight on h → greedier/faster but less optimal; more weight on g → more like UCS.

Branching factor vs state space (they ask this)

Branching factor (b) = how many successors one node has (actions available). State space = the total number of distinct states the problem can be in. Small b, huge state space is typical (b=4, states=2²⁰).

True/False & MCQ fast facts (Spring 2023-24 style)

  • A* is complete and optimal if h is admissible — True.
  • Greedy BFS uses f(n)=h(n); A* uses f(n)=g(n)+h(n).
  • IDS combines DFS's memory with BFS's completeness — True.
  • DFS is complete — False.
  • In α-β, pruning fires when α ≥ β.
  • A crossword solver is a static, single-agent environment; a part-picking robot is not fully observable-only, etc. — read carefully.
  • An environment is uncertain if it is not fully observable or not deterministic — True.

You're ready if you can, from a blank page:
